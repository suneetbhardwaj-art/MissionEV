01 / THE INVISIBLE FOOTPRINT

We track everything.
Except the impact of getting there.

Today, commuters track steps, sleep, and heart rates. Yet the invisible environmental footprint of millions of daily commutes remains unmeasured and unrewarded.

01 / URBAN BURDEN
24%

Invisible Daily Emissions

Transport accounts for roughly a quarter of global direct CO2 emissions from fuel combustion (a figure attributed to the IEA; not re-verified for this site). In this project's model a petrol sedan emits about 196 g CO2e/km, a number commuters rarely see.

02 / DISCONNECTED COMMUTERS
No ledger

No Continuous Personal Ledger

Public transit and EV drivers generate substantial avoided carbon every week, but their choices disappear into thin air without a persistent, portable record of their climate stewardship.

03 / MISSING INCENTIVES
No reward loop

The Missing Reward Loop

Without low-cost, decentralized verifiable micro-rewards, cities lack the behavioral economic engine needed to nudge commuters toward clean transit habits.

06 / BUILT FOR A CONNECTED ECOSYSTEM

Cloud intelligence.
Verifiable incentives.

The intended design pairs an Azure cloud backend with an EVM contract. Every layer below is labelled as implemented, source-only or planned.

LAYER 1: CLIENT FRONTEND EXPERIENCE STATIC WEB APP · IMPLEMENTED
Responsive static web app with the emissions model, a sample dashboard and an optional wallet connector.
LAYER 2: MICROSOFT AZURE (PLANNED) PLANNED · NOT IMPLEMENTED
Design target only: an emissions oracle, route verification and telematics streaming. None of it exists yet.
LAYER 3: PORTAL V3 EVM CONTRACT SOURCE ONLY · DEPLOYMENT UNVERIFIED
EVMobilityRewards.sol records journeys and can pay out an existing ERC-20 reward token. It does not mint, and has no badges.
LAYER 4: STORAGE & ANALYTICS (PLANNED) PLANNED · NOT IMPLEMENTED
Idea only: stored commuter profiles and city-level dashboards. Nothing is stored or analysed today.

LAYER 2: MICROSOFT AZURE CLOUD BACKEND

Deterministic Emissions Oracle, Geofencing & Event Streaming

Azure Functions calculate lifecycle emissions against CEA baseline databases in real-time. Azure Maps performs route snap-to-road distance validation and detects congestion corridors. Azure Event Hubs streams connected EV vehicle telemetry.

TECHNOLOGY STACK: Azure Functions (Serverless Node/C#), Azure Maps REST APIs, Azure Event Hubs, Azure API Management, Azure Key Vault for oracle signing keys.

ENTERPRISE ARCHITECTURE DEEP-DIVE

MissionEV: Microsoft Azure × Portal Layer 0 Architecture

Implemented today: a static web app that computes emissions in the browser, and the source of EVMobilityRewards.sol, which records self-reported journeys on an EVM chain (distance 1 to 500 km, unique journey ID, score and streak, optional token payout from the contract's own balance).

Not implemented (design only): an Azure Functions oracle that would compute and sign emissions, Azure Maps route validation, Event Hubs / IoT telemetry, Cosmos DB storage and Fabric / Power BI dashboards. MissionEV.sol sketches the oracle-signature flow but is not wired to this site.

Trust model: today the caller reports their own distance and the contract applies fixed per-km constants. Nothing prevents false reports until a verification layer exists. Avoided emissions shown anywhere on this site are modelled estimates, not certified carbon credits.
